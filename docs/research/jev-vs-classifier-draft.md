# Jev 与分类器到底有什么区别：从一次公平的 Agent 路由实验开始

> 状态：研究源稿。规则和专用分类器拥有离线证据；Jev 真实调用为 `尚无 live evidence`。本文不得在补齐运行 ID、代码 commit、数据哈希和模型版本前写成实测结论。

## 1. 三个概念并不在同一层

Transformer 是计算架构，分类器是任务形态，Jev 是面向类型化概率决策的模型产品和接口。Jev 从外部看非常像分类器：状态和候选集合进去，标签概率出来。由于权重和完整架构未公开，目前既不能证明它脱离 Transformer，也不能把它断言为普通分类头。

## 2. Jev 与动态分类器的相似之处

传统专用分类器通常固定任务、固定标签并依赖监督训练。Jev 允许调用方在运行时用自然语言定义问题、候选和判断标准。它更接近“自然语言配置的通用判别服务”。这种灵活性是否值得供应商依赖和调用成本，不能靠接口描述回答。

## 3. 为什么不能只看准确率

本研究同时比较决策质量、概率校准、拒答后的覆盖率、训练样本、首次建设步骤、标签变化后的重做工作、推理延迟、模型体积和已知 API 成本。专用分类器可以监督训练；Jev 和 DeepSeek 可以零样本适配。公平不是强迫它们用同一种方法，而是计算完成同一目标的总代价。

## 4. 数据切分与防泄漏

`routing-v1` 含 100 条中文合成样本，按样本族固定为 60 条 dev、20 条 calibration 和 20 条 test。同一意图的改写不能跨分区。规则、特征、Prompt 和 Criteria 只看 dev；calibration 只选阈值；test 只在全部配置冻结后运行。开发集的三折分组交叉验证只说明稳定性，不冒充泛化成绩。

## 5. 三类成本

- 建设成本：标注量、训练步骤、Prompt 或 Criteria 设计、密钥与网络依赖；
- 变更成本：标签调整后是否需要补标、改规则、重训和重校准；
- 运行成本：P50/P95 延迟、API 费用、训练耗时和模型体积。

本地分类器的 API 成本是零，但计算和标注并非免费。远程模型免训练，也不代表没有 Prompt、校准、监控和供应商成本。

## 6. 当前离线证据

实验台已经实现规则、TF-IDF + Logistic Regression、DeepSeek、Jev 与录制回放的统一结果契约。分类器训练会记录数据哈希、训练样本、随机种子、依赖版本、模型哈希、训练耗时和大小；加载时先验证完整性。当前数据集仍是小型合成集，任何结果只适用于这项路由研究。

## 7. 尚未获得的证据

- Jev：`尚无 live evidence`；
- DeepSeek 同口径正式测试：`尚无 live evidence`；
- “193.6 倍更快、444.6 倍更便宜”的独立复核：`尚无 live evidence`；
- 标签拆分后的变更成本成绩：`尚无 live evidence`。

结构合法不等于语义正确。Jev 不生成候选空间之外的字符串，并不能保证它选中的候选正确；最终仍需用本地标注、概率校准、拒答阈值和失败案例验证。
